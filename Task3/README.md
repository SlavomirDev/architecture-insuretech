# Выявленные проблемы

1. Использование синхронных запросов к внешним API страховых компаний
   - При сбое у любой из страховых компаний сервис ins-comp-aggregator блокируется
   - Это приводит к задержкам и ошибкам в работе сервисов core-app и ins-comp-settlement при выполнении REST-запросов
   - С увеличением числа страховых компаний время ответа ins-comp-aggregator может значительно возрасти

2. Несогласованная частота опроса между сервисами
   - ins-comp-settlement запрашивает данные раз в сутки, а core-app — каждые 15 минут
   - В случае остановки ins-comp-aggregator данные длительное время остаются неактуальными
3. Наличие жестких REST-зависимостей между сервисами
   - ins-comp-settlement зависит от core-app для получения информации о страховках
   - Прямые REST-вызовы создают взаимную блокировку сервисов

# Предложения по улучшению

1. Перевести ins-comp-aggregator на асинхронное взаимодействие через брокер сообщений
   - ins-comp-aggregator будет самостоятельно опрашивать страховые компании и публиковать результаты в брокере
   - Сервисы core-app и ins-comp-settlement станут подписчиками соответствующих событий
2. Внедрить transactional outbox в core-app при оформлении страховок
   - Это устранит REST-зависимость ins-comp-settlement от core-app
   - Механизм outbox гарантирует надежную доставку данных без потерь
