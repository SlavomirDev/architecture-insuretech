# Требования к отказоустойчивости системы:
- Время восстановления (RTO) - 45 мин;
- Точка восстановления (RPO) - 15 мин;
- Одинаковое время загрузки страниц для пользователей из разных регионов

## Размещение
   Приложение развернуто в одном кластере Managed Kubernetes, узлы которого распределены между двумя зонами доступности (ru-central1-a, ru-central1-b) в рамках одного региона.

## Масштабирование и отказоустойчивость
   Используется горизонтальное масштабирование.
   Failover стратегия - active-active.
   Сервисы работают одновременно в обеих зонах. При отказе одной зоны нагрузка автоматически перераспределяется.

## Балансировка
   Внешний Load Balancer распределяет входящий трафик между экземплярами сервисов в разных зонах, основываясь на результатах постоянных Health Check.
   А также выполнять роль Rate Limiter'а.

## База данных
   Для обеспечения отказоустойчивости и соответствия RTO/RPO развернут кластер PostgreSQL на основе Patroni.
   Кластер включает мастер и синхронную реплику в разных зонах. HAProxy выступает в роли единой точки входа для приложений, направляя запросы на текущего мастера.
   Консенсус и управление состоянием кластера обеспечивает etcd.
   Резервное копирование выполняется в S3 с помощью PgBackRest.

## Производительность
   Для ускорения загрузки статического контента для пользователей из разных регионов используется CDN (не показан на схеме, но подразумевается).

## Наблюдаемость
   Для мониторинга инфраструктуры и БД используются Prometheus/Grafana, ELK для логов и PMM для детального мониторинга PostgreSQL.
